# 前端接口契约 · 索引

## 这套文档是什么

`frontend/` 目录放的是**前后端之间的接口契约**。目标是：**前端同学拿到这套文档就能开工，不需要问后端任何问题。**

如果你读完某个接口还是不知道该传什么、该处理什么错误，那就是文档的问题，不是你的问题——提出来，我们改。

> 后端内部怎么实现，不在这里讲。想看原理，去同级的 `knowledge/` 目录。编号是对应的：比如 `knowledge/11-对话记忆.md` 讲内部实现，`frontend/20-conversation-会话与消息.md` 讲前端怎么调。

## 怎么读

**第一次接触这个项目，按这个顺序读：**

1. **[01-通用约定](01-通用约定.md)** —— 必须最先读。里面有响应信封、**类型陷阱（id 是字符串不是数字）**、鉴权方式、错误码表。**不读这篇直接看接口，一定会踩坑。**
2. **[03-前端整体架构](03-前端整体架构.md)** —— **动手写第一行代码前读它。** 讲的是代码怎么组织：目录分层、运行状态机、11 种流式事件各自对应什么动作、DeepSeek 那套简约风怎么落地。不读的话，界面能做出来，但会写出一堆风格和数据流都不统一的组件。
3. **[10-user-用户模块](10-user-用户模块.md)** —— 唯一一个**已经实现并验证过**的模块。可以直接照着写登录注册。
4. **[02-SSE协议规范](02-SSE协议规范.md)** —— 对话是流式的，这里的协议和前几个接口长得完全不一样，要单独理解。
5. 然后按你要做的功能读 `20` ~ `60`。

**关于状态**：`10 / 20 / 30 / 40 / 50 / 60` 后端**已实现、可直接联调**（`30` 起含**工具调用**与 `tool_call` / `tool_result` 事件，M8 起运行状态落库；`40` 含停止/继续/重连/人工确认；`60` 含工具清单、调用记录与汇总）。仅 `40` 的执行链 `GET .../steps` 与运行列表 `.../run/list` 还未实现（M13）。

**联调前必读的一处行为（2026-10-14 起，M7 改动）**：`POST /chat/stream` 现在是**工具循环**，**检索不再是「自动」的**——它改成由模型按需调用 `searchKnowledge` 工具（M6 的自动检索已移除）。所以前端会收到 `tool_call` / `tool_result` 事件（**可见了**），可据此渲染「正在检索知识库…」之类的进度提示；中文名用 `GET /tools/list` 的 `displayName` 映射。知识库范围仍由会话关联或请求的 `kbIds` 决定（见 [30](30-chat-对话与流式.md)）。**非流式 `POST /chat/message` 仍无工具、无检索。**

**M8 起（同 2026-10-14）**：`run_start` 的 `runId` 是**真实 `agent_run.id`**（不再是占位 UUID）；**里程碑事件**（`run_start`/`tool_call`/`tool_result`/`run_end`/`interrupt`）的 SSE `id` 是数据库事件 id，**`message_delta` 不带 `id`**。

**M10 起（2026-10-20）**：副作用工具（目前是 `createTicket`）会先挂起并推 `interrupt`，`interruptType=APPROVAL_REQUIRED`，`data.pendingTool` 带参数；前端用 `POST /agent/run/{runId}/approve` 同意/拒绝，详见 [40](40-agent-中断与恢复.md)。

**M12 起（2026-10-20）**：工具调用记录与调用汇总可查：`GET /tools/logs`（分页，支持 `runId` / `toolName` / `success`）、
`GET /tools/logs/summary`（token、成本、工具失败与重放次数）。详见 [60](60-tools-工具.md)。

**对于「未实现」的模块不要空等。** 先用 [03-前端整体架构](03-前端整体架构.md) 第七节的**本地事件回放器**（把 `02-SSE` 里那段完整事件序列做成假数据源），界面和状态机都能立刻开工——包括最难验证的「重连后收到 `message_snapshot`」那条分支。

## 一句话说明这个项目是干什么的

用户能和 AI 对话，对话过程中 AI 可以：

- 查用户自己上传的知识库（RAG）
- 调后端接口帮用户办事（比如建工单）
- **被用户随时打断，之后继续**
- 回答是**流式**输出的（字一个个蹦出来）

## 后端在哪跑

| | |
|---|---|
| 地址（本地） | `http://localhost:8102/api` |
| 接口文档（Swagger/knife4j） | `http://localhost:8102/api/doc.html` |
| 上下文路径 | **所有接口都有 `/api` 前缀** |

`/api` 这个前缀是 `server.servlet.context-path` 配的，不在每个 Controller 的路径里。所以你在 Swagger 里看到的路径可能是 `/user/login`，但实际请求要打 `http://localhost:8102/api/user/login`。**这是第一个容易踩的坑。**
