# 前端接口契约 · 索引

## 这套文档是什么

`frontend/` 目录放的是**前后端之间的接口契约**。目标是：**前端同学拿到这套文档就能开工，不需要问后端任何问题。**

如果你读完某个接口还是不知道该传什么、该处理什么错误，那就是文档的问题，不是你的问题——提出来，我们改。

> 后端内部怎么实现，不在这里讲。想看原理，去同级的 `knowledge/` 目录。编号是对应的：比如 `knowledge/11-对话记忆.md` 讲内部实现，`frontend/20-conversation-会话与消息.md` 讲前端怎么调。

## 怎么读

**第一次接触这个项目，按这个顺序读：**

1. **[01-通用约定](01-通用约定.md)** —— 必须最先读。里面有响应信封、**类型陷阱（id 是字符串不是数字）**、鉴权方式、错误码表。**不读这篇直接看接口，一定会踩坑。**
2. **[03-前端整体架构](03-前端整体架构.md)** —— **动手写第一行代码前读它。** 讲的是代码怎么组织：目录分层、运行状态机、11 种流式事件各自对应什么动作、DeepSeek 那套简约风怎么落地。不读的话，界面能做出来，但会写出一堆风格和数据流都不统一的组件。
3. **[10-user-用户模块](10-user-用户模块.md)** —— 唯一一个**已经实现并验证过**的模块。可以直接照着写登录注册。
4. **[02-SSE协议规范](02-SSE协议规范.md)** —— 对话是流式的，这里的协议和前几个接口长得完全不一样，要单独理解。
5. 然后按你要做的功能读 `20` ~ `60`。

**关于状态**：`10 / 20 / 30 / 50` 后端**已实现、可直接联调**；`40 / 60`（工具、中断恢复）仍是设计定稿、后端未写——先照文档做界面和类型即可，联调留到 M7/M8。

**联调前必读的一处行为（2026-10-13 起生效）**：`POST /chat/stream` 已接**自动检索**——会话关联了知识库（或请求带了 `kbIds`）时，后端会先检索再把命中片段交给模型，**整个检索过程对前端完全不可见**（不推事件）。前端只需负责两件事：把知识库关联到会话（见 [20](20-conversation-会话与消息.md)）、按需在请求里带 `kbIds`（见 [30](30-chat-对话与流式.md)），回答里就会自然带上知识库依据。**非流式 `POST /chat/message` 仍不检索。**

**对于「未实现」的模块不要空等。** 先用 [03-前端整体架构](03-前端整体架构.md) 第七节的**本地事件回放器**（把 `02-SSE` 里那段完整事件序列做成假数据源），界面和状态机都能立刻开工——包括最难验证的「重连后收到 `message_snapshot`」那条分支。

## 一句话说明这个项目是干什么的

用户能和 AI 对话，对话过程中 AI 可以：

- 查用户自己上传的知识库（RAG）
- 调后端接口帮用户办事（比如建工单）
- **被用户随时打断，之后继续**
- 回答是**流式**输出的（字一个个蹦出来）

## 后端在哪跑

| | |
|---|---|
| 地址（本地） | `http://localhost:8102/api` |
| 接口文档（Swagger/knife4j） | `http://localhost:8102/api/doc.html` |
| 上下文路径 | **所有接口都有 `/api` 前缀** |

`/api` 这个前缀是 `server.servlet.context-path` 配的，不在每个 Controller 的路径里。所以你在 Swagger 里看到的路径可能是 `/user/login`，但实际请求要打 `http://localhost:8102/api/user/login`。**这是第一个容易踩的坑。**
