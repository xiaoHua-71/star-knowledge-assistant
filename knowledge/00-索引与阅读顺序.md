# 智能星知识助手 · 知识文档索引

## 这套文档是什么

本项目采用「**文档带动实现**」的做法：每个模块先写清楚「治哪类病 → 官方怎么做 → 本项目怎么落地 → 数据结构 → 边界与坑」，再照着文档写代码。

这样做有三个直接好处：

1. **避免边写边返工**。Agent、中断恢复这类模块真正的难点在状态设计，不在代码量。状态设计想清楚了，代码是机械劳动；没想清楚，代码写完还得推倒。
2. **能自检**。文档里每写下一个「决定」，就要写清楚备选方案和取舍理由。写不出理由的决定，通常就是没想清楚的决定。
3. **能交接**。前端、后续接手的人看文档就够，不用问人。

## 文档在哪

| 目录 | 放什么 | 谁看 |
|---|---|---|
| 本目录 `knowledge/` | 每个模块的**内部流程、设计说明、坑** | 后端开发、自己回顾 |
| 同级 `frontend/` | 与前端交互的**接口契约**，拿到即可开发 | 前端开发 |

两份文档的编号是对应的：`knowledge/11-对话记忆.md` 讲内部怎么实现，`frontend/20-conversation-会话与消息.md` 讲前端怎么调。

## 怎么读

**如果你第一次接触这个项目**，按顺序读：

1. [01-总体架构与路线图](01-总体架构与路线图.md) —— 先建立整体印象：分几层、一共几个阶段、现在在哪
2. [02-模块清单与依赖关系](02-模块清单与依赖关系.md) —— 一共要做哪些模块、谁依赖谁、哪些是必做
3. [03-文档写作约定](03-文档写作约定.md) —— 这套文档自己是怎么写的（含统一术语表）
4. [10-数据模型总览](10-数据模型总览.md) —— 12 张新表 + 三条必须遵守的数据库约定
5. [11-对话记忆](11-对话记忆.md) —— Agent 的地基
6. [12-中断与恢复的状态机](12-中断与恢复的状态机.md) —— 本项目最难的一块

**如果你要改 RAG**：直接读 `20` ~ `24` 一组。
**如果你要改工具调用**：读 `30`，再回来看 `12`（工具幂等是中断恢复的命门）。
**如果你要改流式输出**：读 `31`，前端契约在 `frontend/02`。
**如果你要动前端联调**：去 `frontend/`。

## 编号规则

编号分两段：**十位表示领域，个位表示该领域内的第几篇**。

| 编号 | 领域 |
|---|---|
| `0x` | 总览、约定、索引 |
| `1x` | 基础与横切（数据模型、对话记忆、中断恢复状态机） |
| `2x` | RAG 知识库 |
| `3x` | 工具调用与流式输出 |
| `4x` | 会话与消息管理 |
| `5x` | 可观测性 |
| `6x` | 离线评测与回归 |

## 一条约定

**文档不是写完就冻结的。** 实现过程中如果发现设计不对，**先改文档再改代码**，并把「为什么原来的设计不成立」记在那篇文档的「边界与坑」一节里。过期的文档比没有文档更糟——它会主动误导人。
